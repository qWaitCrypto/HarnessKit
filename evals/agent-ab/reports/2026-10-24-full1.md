## Why B lost

### S1 — the tool and the skill both weakened the decision

Every run in both arms edited the body of the accepted decision `002-session-renewal.md` (A 5/5, B 5/5). The difference is where the retry went: B put it inside the refresh chain 4/5 times, A 2/5.

1. **False "no constraints" signal.** `harnesskit context --for src/auth/session.rs` and `--for src/auth/refresh.rs` return `No related documents`, although the decision names `src/auth/refresh.rs#refresh_token` and `src/auth/session.rs#renew_session` in plain prose. Anchor extraction only picks up backticked references (the cache note's backticked anchors are in `knowledge.lock`; the decision's are not). The skill tells the agent to run exactly this command before editing code, so the empty answer reads as permission.
2. **The skill frames a feature request as an override.** SKILL.md says "Treat decisions as binding unless the user overrides them." B runs read "add an automatic retry" as that override, then rewrote the decision to match the new code.
3. **`context --diff` rewards the rewrite.** After the decision was rewritten, the diff view showed the new text as covering the change and printed "editing the document alongside its code automatically confirms the updated anchor."

### S2 — scenario ambiguity, not a tool gap

All three failing B runs found `docs/notes/cache-observation.md` through `query "billing v8"` or `context --for src/cache/keys.rs`, edited it, and still decided that settlement summaries stay on v7. The note says "Both selectors were still v7 in the on-call sample" without saying both must move. A failed 2/5 for the same reason. S2 measures interpretation of an ambiguous note, so neither arm's result is attributable to HarnessKit. The note needs a clear statement and both arms need a rerun.

### S6 — HarnessKit's own templates create duplicate text

- 2 of 3 failures were duplicates of boilerplate that `harnesskit init` writes into every collection index (for example "`AGENTS.md` or `CLAUDE.md` → `ARCHITECTURE.md` → `docs/index.md` → this index → focused decision." in decisions, design docs, operations and product specs; 20–30 near-identical pairs per run).
- 1 failure copied the whole README into `docs/references/legacy-handbook.md` while keeping the original notes.
- B runs read 92 documents and used 1.75M tokens (median) against A's 59 and 1.00M. The skill gives no bounded workflow for restructuring an existing repository.

### S7 — upgrade works, scope creeps

4/5 upgraded the CLI and skill, migrated the schema and reached `check` 0 errors. The failure appended HarnessKit installation instructions to the product README. One alpha.6-era surprise: `harnesskit update --help` performs an update instead of printing help (fixed in 0.2.0, observed because S7 starts from alpha.6).

## Changes for the next round

Skill (SKILL.md and references):

1. A feature request that conflicts with an accepted decision is not an override. Work inside the boundary the decision allows, or stop and name the decision and the options. Never edit an accepted decision's body to fit a change; replacing a decision needs the user's explicit consent and a superseding decision.
2. Read the full constraining section, not only the context snippet.
3. Do not put tool installation or HarnessKit usage text into product documents; the routing line in AGENTS.md is enough.
4. Restructuring existing docs: move, do not copy; remove the original passage when consolidating; keep the existing layout where it works; a bounded inventory → plan → move workflow.

Product:

1. Extract `path#symbol` and file-path references from document prose (not only backticked) so `context --for` finds decisions that name the code.
2. `context --diff` must flag a rewritten accepted decision as a decision change that needs confirmation, not as an automatically confirmed anchor.
3. `init` templates must not write the same boilerplate paragraph into every collection index.
4. Context and query snippets should prefer the sentence that names the anchored symbol or states the constraint over the first sentence of the section.

Scenario: make the S2 note state that both selectors move together, and rerun S2 in both arms.
